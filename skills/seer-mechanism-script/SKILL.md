# 仙工 SRC2000 机构脚本

先确认待维护脚本的版本、调用入口、目标 RoboKit/Python 版本和改动范围。用副本、替身或已有日志做本地验证；把连接设备、推送、运行现场任务和重启控制器留给另行授权的现场操作。

按问题读参考资料：

- **接口**参考涵盖签名、支持版本、单位、返回值、完成条件和通用旋转脚本的车型适用性。见[接口查询](references/接口查询.md)。
- **导入**与运行环境核对适用于检查 `syspy.rbkSim` 等依赖、拆文件、重启、入口绑定、参数未生效和外部 TCP 调用。见[导入与重启](references/导入与重启.md)。
- **验证**适用于 SDK 示例、离线回放、节拍测量和日志判读。见[模拟与回放](references/模拟与回放.md)。

## 1. 确定动作契约

列出入口、输入及来源、动作顺序、成功判据、失败和取消的收尾。对每项结论标明来源：**仙工通用规则**看官方文档，**SDK 模拟行为**看本地源码，**项目约定**看待维护脚本、调用方和设备契约。遇到版本、单位、返回值或完成条件的冲突，记录原文、代码符号和目标环境缺少的证据；把该项标为待核实。

区分三层设备证据：① 命令发送：代码进入发送分支只证明尝试，传输记录可再确认本机写入；② 设备应答：核对与本次请求匹配的回包及业务结果；③ 物理动作完成：用本次动作的新鲜位置、到位 DI 或经确认的设备状态验证目标与容差。单独报告 `MoveStatus`；作业 `FINISHED` 只表示脚本的完成条件成立。

## 2. 逐帧推进作业

- RoboKit 向 `Module` 传入字典 `args`；启动时调用一次 `__init__(r, args)`，随后周期调用 `run(r, args)`。继承 `BasicModule`，或按通识实现 `run`、`suspend`、`cancel`。通识给出约 20–200 ms 的调用周期；这是参考范围，计时不要按固定帧数换算。
- 每帧按当前阶段做有界工作：按接口约定首次设置目标或下发，后续帧查询、持续驱动或检查截止时间。阶段、截止时间、已发标志和必要读数放在作业实例中。等待返回 `MoveStatus.RUNNING`，满足该作业约定才返回 `FINISHED`，无法继续则记录原因并返回 `FAILED`。终态不再推进动作。保持目标脚本的返回形式；通识、基类和示例的差异见接口参考。
- 暂停时 RoboKit 可反复调用 `suspend(r)`；恢复后继续 `run`；取消调用 `cancel(r)` 后结束。明确暂停时间是否计入超时、恢复是否沿用当前阶段、重复回调如何安全收尾。若脚本实现 `reset(r)`，显式清除作业内状态、计时和遗留资源；具体调用时机以目标版本为准。
- 不用 `time.sleep` 或循环等到位。以单调时钟和跨帧状态表达等待；给同步 I/O、每帧调用数和整个步骤设上限。核对原有速度发布、暂停、取消、异常收尾及联锁；停止请求仍需对应的反馈才能确认停稳。
- 同一帧推进多个子步骤时，检查共享设备、动作联锁和整帧耗时。依次调用的子步骤共用这一帧的时间，同步 I/O 会推迟后续调用。

## 3. 保持参数兼容

把两层参数分开核对。**任务参数**来自 `args`；脚本以 `####BEGIN DEFAULT ARGS####` 和 `####END DEFAULT ARGS####` 包住合法 JSON，声明 `value`、`type`，`complex` 另有 `default_value` 选项。**配置参数**由 `ParamServer` 读取同名 `params/<脚本名>.json`；本地实现保留已有 `value`，缺键时才用代码默认值。修改默认值不能覆盖旧车参数。

保留已有键、类型、单位、缺省行为和覆盖优先级。若允许任务覆盖配置，集中处理白名单、类型、范围和单位，随后重算派生量；区分缺省、`0`、`False`、空字符串和非法输入。对布尔字符串显式解析，不能用 `bool("false")`。新增或迁移参数时，用旧配置、缺键配置和任务覆盖各验证一次。遇到改名或拆文件，先核对参数文件路径和迁移方案。

## 4. 写小改动，做本地验证

- 按 RoboKit 约定提供 `Module` 作业入口。把参数转换、坐标计算和判定与设备 I/O 分开。按职责和目标控制器的加载约束组织文件。变更文件结构时，核对导入路径、参数文件归属和重启要求。
- 新代码用清楚的名称和显式导入；跨单位的量加 `_mm`、`_m`、`_deg`、`_rad` 或 `_s`。注释记录接口前提和现场约定。按目标 Python 版本选语法、类型标注和依赖；新增代码不在导入时连接设备或执行动作。只在 I/O 边界捕获预期异常，保留失败原因；不能把缺读数、异常或超时转成到位。维持原有动作顺序、联锁、容差和重试，除非任务明确要求改这些行为。
- 先做语法、参数 JSON、导入和依赖检查。新脚本按动作契约验证。维护已有脚本时，用同一输入比较改动前后的相关行为。对正常和相关失败分支检查帧状态、命令次数、等待条件、终态及收尾。交付时写清测了哪些入口、替换了哪一层、看到什么，以及哪些结论仍需在目标环境核实。
